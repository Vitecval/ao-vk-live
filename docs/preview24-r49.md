A separate renderer bug was reproduced before changing production code. Two registered meshes can share an immutable vertex snapshot, world matrix, vertex count and index count while selecting different triangles. The static mesh metadata key included the vertex snapshot and counts but omitted the actual index range. This merged their mesh/object/shadow metadata. The shared-vertex / CPU-index path had the same omission. The reproduction retained one shadow instead of two; after both meshes stopped being submitted, its picture differed from the direct-draw reference by 31,433 pixels. Evidence: `build/preview24/stability-r49/REPRODUCTION.json` and `before-*` outputs.

Registered meshes now fingerprint their immutable triangle range once at registration. Mesh metadata keys include that fingerprint. Shared vertices with CPU-provided indices hash the current index range; CPU-only mesh keys also include the complete range rather than a sparse index sample. The normal registered draw path keeps its cached lookup. This fixes the demonstrated collision without changing how AO submits geometry or adding passes.
